## 1. Project Overview

**Genie AI** is a cross-platform mobile application built with **Expo** and **React Native** that serves as an AI-powered gardening assistant. The application helps users identify plant issues, receive diagnoses, and get personalized solutions for their plants.

### Core Concept
- Users can upload photos of their plants
- AI analyzes the plant condition
- System provides diagnosis and recommendations
- Users can chat with the AI for more information
- Plant data and history are maintained

### Supported Platforms
- **Android** (Primary)
- **iOS** (Secondary)
- **Web** (Experimental - via Expo Web)

## 4. Application Flow & Screen Navigation

### User Journey Map

```
1. index.tsx (Splash Screen)
   ↓ [5s auto-redirect]
   
2. login.tsx (Plant Categories)
   ↓ [Click "Get Started"]
   
3. phoneVerification.tsx (Phone Login)
   ↓ [Enter 10-digit phone number]
   
4. otpScreen.tsx (OTP Verification)
   ↓ [Enter received OTP]
   
5. plantUpload.tsx (Capture/Upload Photos)
   ↓ [Select 1+ images from camera or gallery]
   
6. aiChat.tsx (AI Analysis Loading)
   ↓ [Shows progress, animations, "Genie is thinking"]
   ↓ [Backend analyzes images - 5s progress bar]
   
7. diagnosis.tsx (Results)
   ↓ [Plant identified, condition assessed]
   
8. solution.tsx (Recommendations)
   ↓ [View suggested treatments/actions]
   
9. product.tsx (Product Suggestions)
   ↓ [Buy recommended products/solutions]
   
10. history.tsx (View Past Diagnoses)
    ↓ [Access saved analysis records]
```

### Routing Architecture
- **File-based routing** via Expo Router (no route config needed)
- **Stack-based navigation** with slide animations from right
- **Tab navigation** support (not currently heavily used in (tabs) folder)
- **Deep linking** enabled via `scheme: "genieai"` in app.config.js

## 5. Key Pages & Their Responsibilities

### `app/index.tsx` - Splash Screen
- **Duration:** 5 seconds
- **Display:** Genie AI branding + robot animation (GIF)
- **Purpose:** Initial app load, brand impression
- **Auto-routes to:** `/login`

### `app/login.tsx` - Plant Categories Screen
- **Type:** Animated discovery/marketing screen
- **Features:**
  - Typing animation for main title
  - Sequential card animations for 10 plant species
  - Scrollable plant category grid
  - "Get Started" button (fixed at bottom)
- **Next step:** `/phoneVerification`
- **Supported plants:** Areca Palm, Rose, Tomato, Hibiscus, Snake Plant, Croton, Money Plant, Peace Lily, Curry, Fiddle Leaf Fig

### `app/phoneVerification.tsx` - Phone Login
- **Input:** 10-digit Indian phone number
- **Validation:** Formatted as `XXXXX XXXXX`
- **API Call:** POST `/auth/send_otp` with mobile number
- **Error handling:** Shows alerts on failure
- **Routes to:** `/otpScreen?mobile={cleanNumber}`
- **Environment:** Uses `BASE_URL` from Expo config

### `app/otpScreen.tsx` - OTP Verification
- **Input:** 6-digit OTP code
- **Verification:** POST to backend
- **Success:** Stores auth token, redirects to upload

### `app/plantUpload.tsx` - Image Capture/Selection
- **Features:** Camera access or gallery selection
- **Multiple uploads:** Can select multiple plant photos
- **Processing:** Converts images to formdata for API
- **Routes to:** `/aiChat` with image parameters

### `app/aiChat.tsx` - AI Analysis Progress
- **Status:** Shows "loading" state with animations
- **Display Elements:**
  - Sparkles header
  - GenieThinking animation component
  - Uploaded images preview
  - Analysis steps (Camera → Brain → Lightbulb)
  - Progress bar (5 seconds)
- **Smart redirect:** Auto-routes to `/diagnosis` when backend ready
- **Parameters:** Receives `result`, `images`, `status` from route

### `app/diagnosis.tsx` - Results Display
- **Shows:** Plant identification + condition assessment
- **UI:** Card-based layout with results

### `app/solution.tsx` - Treatment Recommendations
- **Shows:** Suggested solutions for identified issues
- **Actions:** User can explore or proceed to products

### `app/product.tsx` - Product Recommendations
- **Shows:** Purchasable items to solve the plant issue
- **Integration:** Links to e-commerce or product catalog

### `app/history.tsx` - Diagnosis History
- **Shows:** Past plant analyses
- **Features:** Browse saved records, compare histories

## 7. API Integration

### Backend URL
- **Development:** `http://localhost:8000` (via .env)
- **Production:** (To be configured in .env)

### Key Endpoints Used

#### Authentication
- **POST `/auth/send_otp`**
  - Body: `{ mobile: "10digitnumber" }`
  - Response: `{ message: "success", ... }`
  - Error: Returns 400+ with detail message

- **POST `/auth/verify_otp`**
  - Body: `{ mobile: string, otp: string }`
  - Response: Token/auth data

#### Plant Analysis
- **POST `/analyze/plant` or similar**
  - Body: FormData with images
  - Response: `{ diagnosis: {...}, recommendations: [...] }`

### Axios Configuration
- Currently uses vanilla `fetch()` API in phoneVerification
- **Recommendation:** Create centralized API client using axios for consistency

## 18. Architecture Decisions & Rationale

### Why Expo?
- Cross-platform development (Android, iOS, Web) from single codebase
- No native build setup required initially
- EAS Build for cloud compilation
- Hot reload during development
- Managed services (camera, image picker, etc.)

### Why File-based Routing?
- Modern routing pattern (similar to Next.js)
- Automatic route generation from file structure
- Less boilerplate than traditional route configuration
- Easy to understand folder hierarchy

### Why React Native over Flutter?
- JavaScript ecosystem (npm, JavaScript developers)
- Reusable component architecture
- Easier integration with web (React shared libraries)
- Larger community and ecosystem

### API Integration Pattern
- Currently using fetch API with Axios dependency installed
- **Recommendation:** Create `services/api.ts` with axios client for centralized API management

## 23. Common Development Workflows

### Adding a New Page
1. Create `app/newpage.tsx`
2. Import components and hooks
3. Define styles with `StyleSheet.create()`
4. Export default component
5. Route to it using `router.push('/newpage')`

### Creating a New Component
1. Create `components/MyComponent.tsx`
2. Use TypeScript for prop types
3. Export as default or named
4. Add to `components/index.ts` if frequently used

### Styling a Component
1. Define inline styles object at bottom of file
2. Use `StyleSheet.create()` for performance
3. Reference theme colors from `constants/Colors.ts`
4. Test responsive layout with different screen sizes

### Integrating an API Endpoint
1. Add fetch/axios call in page or custom hook
2. Handle loading/error states
3. Store response in state or context
4. Update UI based on state changes
